Снимок на момент merge PR #10 (лут и инвентарь). Документ описывает то, что
есть в `src/` фактически, включая отступления от CLAUDE.md. Обновляется вместе

## 1. Карта модулей

### Точка входа

| Файл | Отвечает за | Импортирует |

### `src/lib/game/` — логика (13 файлов, 7 боевых + 6 тестовых)

| Файл | Отвечает за | Импортирует |
|---|---|---|
| `numbers.ts` | реэкспорт `Decimal` (задумывался единственной точкой импорта), `formatNumber` (1.23K/4.56M/…/1.00e15) | break_infinity.js |
| `formulas.ts` | `upgradeCost` (base·1.15^owned), `xpToNextLevel` (floor(10·L^1.5) с эпсилоном против погрешности pow), `applyXp` (перенос остатка, мультиуровень, предохранитель 100 000 уровней/вызов) | numbers, types |
| `loop.ts` | планировщик: rAF + аккумулятор, фикс. шаг `STEP_MS=100`, максимум 10 шагов/кадр, сброс «долга» после заморозки; метрики fps/tps раз в секунду. Не знает про состояние игры — только вызывает `step(dtMs)` | — |
| `tick.ts` | **сердце игры**: `GameState`, `createInitialState`, `tick(state, dtMs, rng)` — бой, награды, уровни, дроп лута, респаун (300 мс), лог боя строками | numbers, formulas, loot, data/monsters, data/rarity, types |
| `upgrades.ts` | `buyUpgrade` (проверка золота → списание → +урон → счётчик), `ownedCount` | numbers, formulas, tick, types |
| `loot.ts` | `rollRarity` (взвешенная рулетка), `rollLoot` (шанс 25% + генерация имени), `sellItem`/`sellPrice`, `INVENTORY_SIZE=12` | numbers, tick, data/rarity, data/loot, types |
| `save.ts` | формат сейва v2, миграции, localStorage (инжектируемый), оффлайн-прогресс агрегатом, base64 экспорт/импорт | numbers, formulas, tick, data/monsters, data/rarity, types |
| `index.ts` | фасад: реэкспорт всего публичного | все выше |

Циклов импортов нет: numbers ← formulas ← tick ← {upgrades, loot, save}.
Внимание: `loot.ts` и `tick.ts` импортируют друг друга (loot → тип `GameState`
из tick, tick → функции из loot); это работает, потому что в одну сторону
уходит только тип, но связка хрупкая.

## 2. Состояние

- Живёт в одном `writable<GameState>` в `stores/game.ts`. Полный состав
  `GameState` — в `tick.ts`: totalTicks, playtimeMs, gold, level, currentXp,
  xpToNext, baseDamage, upgrades, inventory, itemSeq, monster, respawnMsLeft,
  combatLog.
- Меняют его ровно четыре пути, все через `state.update/set` в сторе:
  1) игровой цикл — `tick()` каждые 100 мс;
  2) экшены покупки/продажи по кликам;
  3) `initGame()` — установка загруженного состояния при старте;
  4) `importSaveString()` — замена состояния целиком.
- UI читает только `$gameState` (readonly) и производные считает в компонентах
  (`$derived` для процентов полосок). Прямых мутаций состояния из UI нет.
- `tick` — чистая функция «состояние → состояние», каждый шаг создаёт новый
  объект. Случайность — параметр `rng` (по умолчанию `Math.random`).

## 3. Бой

- Весь бой — внутри `tick()` в `tick.ts`. Отдельного модуля боя нет.
- Урон за шаг: `baseDamage × dtMs / 1000` (baseDamage — это урон в секунду).
  Источник числа: стартовые 10 захардкожены в `createInitialState()`
  (**не в `data/`**), дальше только покупки заточки добавляют по +1
  (`buyUpgrade` мутирует `baseDamage` накопительно).
- `statBonus` предметов инвентаря к урону **не применяется** — это заготовка
  под пункт 7 (экипировка). Сейчас предмет влияет на игру только ценой продажи.
- HP моба: из `data/monsters.ts` через `spawnMonster` (копия шаблона с полным
  HP). `currentHp <= 0` → фиксированные награды моба → `applyXp` → дроп лута →
  `respawnMsLeft = 300`; следующие 3 тика идёт отсчёт, потом спавн.
- Спавнится **всегда `FIRST_MONSTER`** — выбор моба/зоны нигде не
  параметризован.
- Оффлайн-бой считается отдельной формулой в `save.ts` (не через tick):
  цикл убийства = `maxHp/baseDamage + 0.3 c`, убийства = floor(время/цикл),
  награды умножением. Лут в оффлайне не выпадает.

## 4. Сохранение

- Текущая версия формата: **2** (`SAVE_VERSION` в `save.ts`), ключ
  `idle-rpg-save`. Автосейв: каждые 15 с игрового времени + `visibilitychange`.
- Реальный формат — `SavePayloadV2` (НЕ `SaveData` из types!), все Decimal —
  строки через `toString()`:

  | Поле | Тип | Что хранит |
  |---|---|---|
  | `version` | number | 2 |
  | `lastTimestamp` | number | Date.now() на момент сохранения (оффлайн-прогресс) |
  | `gold` | string | золото |
  | `level` | string | уровень |
  | `currentXp` | string | опыт до следующего уровня |
  | `baseDamage` | string | урон в секунду |
  | `upgrades` | Record<string,string> | id апгрейда → куплено |
  | `inventory` | {id,name,rarity,statBonus}[] | предметы (statBonus строкой) |
  | `itemSeq` | number | счётчик id предметов |
  | `totalTicks` | string | всего тиков |
  | `playtimeMs` | string | игровое время |

  НЕ сохраняются (восстанавливаются заново): monster/respawn (свежий спавн),
  combatLog (пустой), xpToNext (пересчёт из level).
- Миграции (`MIGRATIONS` в `save.ts`), цепочкой v→v+1:
  - **0→1**: «доверсионный» сейв без поля `version` — перенос известных полей,
    остальное дефолты;
  - **1→2**: добавляет пустые `inventory` и `itemSeq: 0`.
  - Сейв с `version > 2` не грузится (понятная ошибка, не белый экран).
  - Битый JSON → try/catch → чистый старт + сообщение в баннере.
- Защиты: отрицательная разница времени (часы назад) не начисляет ничего;
  оффлайн-потолок 8 часов; неизвестная редкость предмета деградирует до
  common; отсутствие localStorage не роняет игру.
- Экспорт/импорт: base64 того же JSON; импорт понимает и голый JSON, и
  прогоняет вход через ту же цепочку миграций.

## 5. Расхождения с CLAUDE.md

По четырём горячим точкам из задания:

- **Логика знает про DOM/Svelte/UI**: про Svelte и DOM-рендер — нигде. Но
  `src/lib/game` знает про **браузерные API** (не DOM): `loop.ts` по умолчанию
  берёт `requestAnimationFrame`/`performance.now`, `save.ts` —
  `localStorage`/`Date.now`/`btoa`. Всё инжектируется и в тестах подменяется,
  однако буква правила «game не знает про платформу» соблюдена не полностью.
  Плюс `tick.ts` генерирует **русские строки лога** («повержен!», «Выпало:») —
  это текст интерфейса, живущий в логике.
- **Игровые числа не-Decimal**: `respawnMsLeft` (мс), `itemSeq`, `dtMs`,
  `DROP_CHANCE` (0.25 — это игровой баланс!), веса редкостей, `STEP_MS`,
  пороги/потолки сейва (8 ч, 15 с), `lastTimestamp`, fps/tps. Часть из них
  документирована как «служебные» — но `DROP_CHANCE` и веса рулетки со всей
  честностью игровые величины, просто завязанные на `Math.random(): number`.
- **Данные хардкодом вне `data/`**: стартовый `baseDamage = 10` — в
  `createInitialState()` (tick.ts); `RESPAWN_DELAY_MS = 300` — в tick.ts;
  `INVENTORY_SIZE = 12` — в game/loot.ts; потолки оффлайна — в save.ts. Это
  баланс, которому место в `data/`. В компонентах игровых данных нет, но
  «декоративные» константы (цвет золота `#d4a017`, цвет опыта `#7e6fff`)
  продублированы в 4+ компонентах.
- **Таймеры в компонентах**: игровых нет. Есть один косметический
  `setTimeout` в `SaveControls` (возврат надписи кнопки через 2 с после
  «Скопировано ✓») — правило говорит «для игровой логики», так что формально
  чисто, но это единственный таймер вне цикла.

Прочие расхождения:

- CLAUDE.md: «stores — единственный мост между логикой и UI». Фактически
  4 компонента импортируют функции напрямую из `../game` (`formatNumber`,
  `upgradeCost`, `ownedCount`, `sellPrice`, `INVENTORY_SIZE`) и данные из
  `../data` (`RARITY_BY_ID`, `UPGRADES`). Это чтение чистых функций/констант,
  состояние они не трогают — но мост уже не единственный.
- `types/index.ts` обещает `Character`, `Zone`, `SaveData` — код их не
  использует: вместо `Character` — плоские поля `GameState`, вместо
  `SaveData` — `SavePayloadV2`, `Zone` не реализован. Типы-фантомы вводят в
  заблуждение.
- `numbers.ts` задуман единственной точкой импорта `Decimal`, но
  `types/index.ts` импортирует `break_infinity.js` напрямую (только тип).

## 6. Техдолг под экипировку, умения, таланты и зоны

| # | Долг | Оценка | Почему |
|---|---|---|---|
| 1 | **Урон — накопительная мутация, а не пересчёт из источников.** `baseDamage` = стартовые 10 + все купленные +1 навсегда. Вклад отдельного источника невычитаем: надетый предмет нельзя будет снять, талант — сбросить. Нужен derived-слой: `effectiveDamage = f(уровень, апгрейды, экипировка, таланты)`, пересчитываемый из счётчиков. | **Блокирует** экипировку (пункт 7) и таланты | Продажа надетого предмета иначе навсегда изменит урон |
| 2 | **Моб захардкожен: `tick` всегда спавнит `FIRST_MONSTER`.** Ни `currentZoneId` в состоянии, ни выбора из пула — `Zone.monsterPool` существует только как мёртвый тип. | **Блокирует** зоны (пункт 6) | Спавн должен стать функцией от текущей зоны; сейв потребует v3 (`currentZoneId`) |
| 3 | **Оффлайн-формула дублирует бой.** `save.ts` считает «цикл убийства» из maxHp/dps в обход tick. Любая новая механика (крит от умений, DoT, множители зоны) должна будет отражаться в двух местах, иначе оффлайн начнёт врать. | **Мешает** всем боевым фичам | Аггрегат правильный по производительности, но нужен единый источник «убийств в секунду» |
| 4 | **Монолитный `tick`.** Бой, награды, уровни, дроп и респаун — одна функция. Умения/таланты (события «при убийстве», «при ударе») потребуют пайплайна шагов или системы событий. | **Мешает** умениям/талантам | Расширение через if-ы быстро станет нечитаемым |
| 5 | **Лог боя — готовые строки в логике.** Нельзя подсветить редкость в логе, перевести язык или отфильтровать события; UI-текст рождается в tick. Правильнее — структурированные события `{type, payload}` с рендером в UI. | **Мешает** (UI-полировка, пункт 8) | Придётся переписать лог при первом же требовании к его виду |
| 6 | Баланс разбросан: стартовый урон в tick.ts, респаун в tick.ts, размер инвентаря в loot.ts, потолки оффлайна в save.ts — а не в `data/`. | Терпит | Мешает только настройке баланса, механики не ломает |
| 7 | Типы-фантомы в `types/index.ts` (`Character`, `Zone`, `SaveData`) и прямой импорт break_infinity там же. | Терпит | Риск, что новая фича обопрётся на неиспользуемый тип |
| 8 | Взаимный импорт `tick.ts` ↔ `loot.ts` (в одну сторону — только тип). | Терпит | Разорвётся сам, если `GameState` переедет в отдельный `state.ts` |
| 9 | `rng` по умолчанию `Math.random` внутри `tick` — реплеи/сид-раны потребуют прокинуть rng из цикла. | Терпит | Тестов уже не касается (там rng инжектируется) |
| 10 | Дубли декоративных цветов (золото/опыт) по компонентам. | Терпит | Чисто косметика; цвета редкостей уже централизованы |

Рекомендуемый порядок перед пунктами 6–7 дорожной карты: сначала №1
(пересчёт урона из источников) и №2 (параметризация спавна зоной + сейв v3) —
они блокируют; №3 закрыть заодно с №2, выведя «убийств в секунду» в одну
функцию, которой пользуются и tick-баланс, и оффлайн.
